# 公平分配教學網站——設計規格（繁體中文）

## 目標與對象

建立公開、可分享、支援繁體中文與英文的網站，讓不熟悉不可分割物品公平分配的同事透過評價分配結果、建立案例及競賽，理解 EF1、EFX 和納許社會福利（Nash social welfare，NSW）。匿名評分用來比較數學標準與訪客的直覺；這些自願參與的資料不是具代表性的研究樣本。

## 功能範圍與學習流程

1. **引導範例：** 準備少量精選案例，使用非負、可加的估值，介紹參與者、不可分割物品、估值、分配、嫉妒、EF1、EFX 與 NSW。訪客先以 1 至 5 分評價某項分配（「非常不公平」至「非常公平」），**評分前不得看到**形式化指標或判定結果。提交後才顯示解釋、彙整評分及下一個範例。
2. **建立案例：** 訪客輸入參與者、物品，以及每位參與者對每件物品的非負整數估值。每份提交的分配須將每件物品恰好交給一人。發布後產生不可修改、可分享的案例連結；若要更改估值，需另建新案例。發布前提供預覽及清楚的輸入驗證訊息。
3. **同案例競賽：** 訪客可為案例分配所有物品並提交結果；排行榜依**原始 NSW** 排序。系統提供可重現的隨機輪流挑選基準：儲存隨機種子以確定參與者輪次，每人輪到時選取自己估值最高的剩餘物品，同分時按物品順序選擇。基準分配須明確標示，不歸屬任何訪客。排行榜只比較同一案例內的分配，因此原始分數可直接比較。
4. **先評價、後揭曉：** 評價某項分配時，先隱藏其 EF1／EFX 判定、NSW、名次、其他人的評分與可分割物品的比較結果。訪客提交 1 至 5 分後，才顯示這些資訊、解釋與評分分布。若同一瀏覽器已評價該分配，直接顯示結果而不接受該瀏覽器再次評分。這只能降低誤觸重複投票，不能驗證每人只投一次。
5. **理解計算難度：** 說明計算「已給定分配」的 NSW 很直接，但尋找 NSW 最大的不可分割分配在計算上困難（適當定義的判定版本為 NP 完全）。解釋非負可加估值下 EF1 分配總是存在，但不暗示 EFX 有相同的存在性結論。不可把啟發式解或可分割物品的解稱為不可分割情況的最優解。

## 語言與在地化

- 首版完整支援繁體中文（`zh-TW`）及英文（`en`），涵蓋導覽、教學、評分選項、數學解釋、輸入錯誤、載入狀態及結果摘要。首次進入時依瀏覽器語言選擇（`zh-TW` 用繁體中文，其餘預設英文）；訪客可手動切換，選擇儲存在瀏覽器中。
- 兩種語言共用同一套案例、ID、分配、投票、指標及排行榜。切換語言不應重複投票或重啟學習流程。精選案例的解說提供雙語版本；訪客自行輸入的參與者與物品名稱保持原文，不自動翻譯。分享連結在兩種語言下都能使用。

## 數學模型與回饋

- 一位參與者對自己所得物品組合的價值，等於各件物品估值之和；估值為非負整數。NSW 是**所有參與者所得組合價值的乘積**。只要有人取得價值為零的組合，NSW 就是零；相同乘積視為並列，不以其他公平指標硬性打破平手。大型乘積以精確十進位整數顯示，不依賴浮點數乘法。
- **EF1：** 對任意不同的參與者 i、j，若 i 嫉妒 j，須存在 j 所得的一件物品，移除後 i 就不再嫉妒 j。
- **EFX：** 本站採用「i 給予正估值的物品」定義：對任意 i、j，以及 j 所得且 i 給予正估值的每件物品，移除該物品後 i 都不再嫉妒 j。網站須明示此定義，判定不成立時提供具體的參與者組合，並在適用時指出相關物品。
- 顯示各人的所得價值，以及 EF1／EFX 判定的簡要理由。輪流挑選基準與使用者提交的分配，均使用伺服器端同一套經測試的評分邏輯；前端可供預覽，但不能提供受信任的分數。
- 另行估算**同一案例中容許物品按比例切分時的最優 NSW**：每件物品分給各人的比例總和為一，目標是最大化所得價值的乘積。此為可分割版本的放寬問題，不是不可分割版本的最優解。數值求解使用獨立、設有時間限制的請求，結果按不可修改的案例 ID 快取。若無法證明數值精度足夠，應標記為「數值估計」，而非已驗證的上界。若求解逾時、失敗或耗用資源過多，顯示「可分割版本比較暫不可用」，排行榜與投票仍照常運作。明確處理任何分配都只能得到零 NSW 的案例。數學模型不任意規定極小的參與者或物品數量上限，但公開服務須有請求大小、運算時間及資源限制。

## 架構與資料

- 網站包含教學、案例編輯、案例頁、分配編輯、評分與結果介面。使用**外部受託管的 PostgreSQL 資料庫**（例如 Supabase）儲存精選與使用者案例、估值矩陣、建立時間、不可修改的提交分配、伺服器計算的指標、基準隨機種子、匿名 1 至 5 分評價，以及可分割版本的求解狀態與快取結果。案例及分配 ID 用於分享連結。
- 伺服器端介面負責驗證與發布案例、產生輪流挑選基準、驗證分配並評分、接收評價，以及回傳評分分布、投票數與平均值。評分邏輯集中於可獨立測試的模組。資料庫寫入金鑰不得暴露於瀏覽器；所有公開寫入均須有伺服器端驗證及存取規則。
- 獨立且有資源限制的運算服務按需計算可分割版本並快取結果；一般頁面與排行榜不等待它。介面區分「計算中」、「估計結果」及「無法取得」。數值方法必須遵守物品切分比例與非負效用的限制。
- **部署：** 提供兩個 Docker 映像檔及一份 Docker Compose 設定，可部署到同一部機器。Next.js 網站容器從單一公開埠提供前端頁面及 API；求解器容器只在 Compose 私有網路內可連線。PostgreSQL 由外部管理，不由 Compose 啟動，而且只有網站容器連線資料庫。須提供可重現的正式環境建置、環境變數注入密鑰（不寫入映像檔）、網站與求解器健康檢查、啟動相依設定、可重複執行的一次性資料庫遷移指令，以及日誌與重啟方式說明。機器上的反向代理負責 HTTPS 並轉送至網站容器；求解器埠不得對主機公開。公開服務仍須設定外部資料庫連線及 DNS／TLS，但這兩者與反向代理都不包含在這兩個映像檔中。
- 匿名訪客不須註冊；不蒐集姓名或電子郵件。評價資料記錄分數、分配 ID 與時間，不把 IP 位址當成問卷資料保存。用瀏覽器本機的「已評價分配 ID」避免意外重複提交，並註明有心人士仍可重複投票。案例、分配及投票介面均須限制請求頻率、輸入大小與數值範圍，輸出時正確跳脫使用者內容；適用範圍亦包含精選案例的相關操作。
- 評分按**每項分配**彙整，不跨不同估值案例合併。平均分數旁顯示票數與 1 至 5 分分布。不可聲稱結果代表一般大眾，或證明某項數學概念客觀上就是公平。

## 錯誤處理與驗證

- 對不合法的估值矩陣、非整數／負數／超出允許範圍的估值、重複或遺漏的物品歸屬、無效案例／分配 ID，以及過大的請求，提供可採取行動的錯誤訊息。沒有參與者或物品的案例不能發布。網路失敗時提供重試途徑；伺服器確認接收評分前，不在瀏覽器記錄已投票。
- 發布與分數儲存須具交易一致性，避免出現沒有可信分數的分配。案例發布後不可修改。同一瀏覽器未完成評分前，預期介面應隱藏彙整結果；即使其他途徑可取得公開彙整資料，這仍是教學流程要求，而非安全保證。
- 可分割版本求解失敗不得妨礙其他功能；應明確標示結果不可用或僅為估計，避免暗示不實的精度。外部資料庫無法連線時，網站的就緒檢查須失敗，寫入 API 須回覆可重試的「服務暫時不可用」，不能讓訪客誤以為投票或案例已成功保存。

## 驗證方式

- 以人工可核對的小案例單元測試 NSW（含零值與巨大乘積）、EF1、EFX（含零估值物品與反例說明）、組合價值、分配合法性及可重現的輪流挑選與同分規則。
- 以可解析求解的小案例測試可分割版本的限制與結果；測試逾時或不可用時其餘功能仍可運作。
- 整合測試「建立 → 發布 → 分享 → 提交分配 → 揭曉前評價 → 彙整 → 排行榜」，確認預期介面在評價前不顯示指標或其他人的評價；並測試不合法請求、濫用限制與同瀏覽器重複評價。
- 兩種語言均須檢查完整教學與評分流程、瀏覽器語言預設、手動切換與保留設定、分享連結、錯誤訊息及求解狀態翻譯。審閱兩種語言的教學文案，確保 NSW「計算」與「最佳化」的區別、EF1 存在性的前提、EFX 定義及問卷限制都正確。
- 以 Compose 在連接一次性外部 PostgreSQL 的條件下建置並啟動兩個正式環境映像檔；依文件指令執行資料庫遷移，確認網站公開埠可提供實際前端頁面與 API、求解器未向主機開放，並檢查健康狀態、重啟行為及資料庫／求解器故障時的處理。

## 首版不包含

使用者帳號、可靠的一人一票驗證、具代表性的統計推論、跨案例 NSW 排名、經認證的不可分割版本最優 NSW、無限制的計算時間，以及修改已發布案例。
